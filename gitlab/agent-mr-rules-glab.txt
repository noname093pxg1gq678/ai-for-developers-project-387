Правила сдачи работы (команда пришла из MR - правки идут в head-ветку этого MR; обязательны, если команда просит изменить код):
- Ты работаешь в head-ветке MR MR_SOURCE_BRANCH: она уже чекаутнута в рабочей копии, коммить прямо в текущий HEAD. Новые ветки не создавай, MR не создавай, git push не выполняй.
- Коммиты в формате Conventional Commits.
- Перед финальным коммитом прогони доступные проверки: mise run check и mise run test:relay.
- Запиши имя ветки в файл agent-branch.txt в корне рабочей копии (только имя ветки, без переводов строк сверх необходимого). Файл обязателен при ЛЮБОМ коммите в HEAD, включая удаление файлов, правки документации и служебных файлов: без него публикация не выполнится, а коммиты останутся на раннере и будут потеряны. Не создавай файл, только если ты не сделал ни одного коммита.
- Публикацию делает отдельный шаг пайплайна: он запушит HEAD в head-ветку MR и обновит MR.
- Работа ведётся в GitLab: используй glab (GITLAB_TOKEN и GITLAB_HOST уже заданы), не gh.
- Remote origin удалён из чекаута джобой, токенов пуша у тебя нет и не должно появляться: не пытайся его восстанавливать и не записывай токены в файлы.
