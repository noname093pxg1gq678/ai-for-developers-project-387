# Деплой через MCP

Сервис выкладывается из Docker-образа (корневой `Dockerfile`), приложение внутри слушает порт из переменной окружения `PORT` - платформа предоставляет её сама.

## Хостинг: Railway

Render был выбран первым, но с сети проекта его домены (`mcp.render.com`, `api.render.com`) недостижимы - соединения сбрасываются на сетевом уровне. По инструкции шага использован запасной вариант: Railway с тем же Docker-образом и запуском по `PORT`.

## Подключение MCP-сервера Railway

Railway использует OAuth: токены хранятся вне конфигурации, в репозитории и переменных окружения их нет.

1. Заведите аккаунт Railway (быстрее всего - вход через GitHub).
2. Конфигурация агента уже в репозитории: `opencode.json` подключает remote MCP-сервер `https://mcp.railway.com/mcp` без заголовков и секретов.
3. Авторизуйтесь: в OpenCode выполните `/mcps`, выберите `railway` и завершите вход в браузере. Альтернатива из терминала: `opencode mcp auth railway`.
4. Проверка: `opencode mcp list` показывает `railway connected`.

## Правила безопасности

- Секретов в репозитории нет: OAuth-токены живут вне конфигурации, ключи платформы не используются.
- Если понадобится токен-схема (railway.com/account/tokens) - ключ только в переменной окружения через подстановку `{env:RAILWAY_API_KEY}`, в конфиге и Git его не хранить.

## Что делает агент после подключения

1. Создаёт сервис из репозитория (Dockerfile, ветка main).
2. Ждёт деплой, проверяет `/api/health` и публичный URL.
3. Прогоняет сценарий гостя и владельца по публичной ссылке, включая отказ повторного бронирования.
4. Добавляет ссылку в README.
